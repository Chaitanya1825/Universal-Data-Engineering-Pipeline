# Power BI Power Query (M) Guide

This guide outlines best practices for connecting to PostgreSQL and configuring Power Query (M) transformations within Power BI Desktop.

---

## 1. Architectural Philosophy: ETL Boundary Separation

> [!IMPORTANT]
> **Keep Heavy Transformations in the Python Pipeline**:
> The Universal Data Engineering Pipeline already executes comprehensive data ingestion, schema profiling, missing-value imputation, type conversion, string normalization, and data-quality validation (Stages 2 through 5).
> **Do not repeat these heavy transformations in Power Query.**
> 
> Power BI's Power Query engine should focus strictly on:
> * Navigation and column selection.
> * Final data-type verification.
> * Dimensional query splitting or simple parameter-driven filtering.

---

## 2. Sample Power Query M Connection Script

When connecting directly to PostgreSQL, Power Query generates an M query similar to the following:

```powerquery
let
    // Connect to PostgreSQL database using parameters or coordinates
    Source = PostgreSQL.Database(
        "YOUR_POSTGRES_SERVER", 
        "YOUR_DATABASE", 
        [CreateNavigationProperties = false]
    ),
    
    // Navigate to the target schema (e.g. public)
    SchemaTable = Source{[Schema="public"]}[Data],
    
    // Select the analytical table generated by the pipeline
    TargetTable = SchemaTable{[Name="your_target_table"]}[Data],
    
    // Verify column data types
    TypedTable = Table.TransformColumnTypes(TargetTable, {
        {"id", Int64.Type},
        {"metric_value", type number},
        {"category_name", type text},
        {"timestamp_col", type datetimezone}
    })
in
    TypedTable
```

## 3. Recommended Power Query Practices

### A. Removing Unnecessary Columns
* Remove technical pipeline columns (such as internal checksums or raw audit paths) if they are not needed by report consumers.
* Reducing column count significantly decreases Power BI VertiPaq memory footprint.

### B. Query Folding
* **Definition**: Query folding is Power Query's ability to translate M transformations into native SQL executed on the source PostgreSQL database engine.
* **Preserving Folding**: Simple operations like `Table.SelectRows` (filtering), `Table.SelectColumns` (projection), and joins fold into native `WHERE`, `SELECT`, and `JOIN` clauses.
* **Breaking Folding**: Complex custom functions, index columns, or non-SQL transformations break folding, forcing Power BI to pull all rows across the network and process them locally in memory.

### C. Parameterizing Connection Strings
To easily transition reports between Development, Staging, and Production environments:
1. In Power Query Editor, click **Manage Parameters** -> **New Parameter**.
2. Create:
   - `ServerName`: Text parameter (default: `localhost`).
   - `DatabaseName`: Text parameter (default: `pipeline_db`).
3. Update connection steps to reference parameters:
   ```powerquery
   Source = PostgreSQL.Database(ServerName, DatabaseName)
   ```
This avoids hardcoding server names across dozens of queries.
