# Power BI Connection Guide: PostgreSQL to Power BI Desktop

This guide describes how to connect Microsoft Power BI Desktop to the PostgreSQL analytical database generated by the Universal Data Engineering Pipeline.

---

## 1. Prerequisites

1. **Power BI Desktop** (Latest version installed on Windows).
2. **Npgsql PostgreSQL Provider** (Included natively with modern Power BI Desktop; if prompted, install the Npgsql .NET data provider).
3. **Database Connectivity**: Access to the host running the PostgreSQL instance (either local `localhost` or remote cloud/network host).

> [!CAUTION]
> **Credential Safety**: Never commit database passwords, connection strings, or `.pbix` files with cached sensitive credentials into version control. Always use environment variables or Power BI parameter prompts.

---

## 2. Step-by-Step Connection Instructions

### Step 1: Open Power BI Desktop
Launch Power BI Desktop on your workstation and create a new report or open an existing workspace.

### Step 2: Select "Get Data"
1. On the **Home** ribbon, click **Get Data**.
2. Select **More...** to open the full data source catalog.
3. In the search box, type `PostgreSQL` and select **PostgreSQL database**, then click **Connect**.

### Step 3: Enter Connection Coordinates
A connection dialogue will appear requesting server and database coordinates:

* **Server**: `YOUR_POSTGRES_SERVER` (e.g., `localhost` or `localhost:5432` or your remote host name).
* **Database**: `YOUR_DATABASE` (the target PostgreSQL database specified in your pipeline configuration, e.g., `pipeline_db`).
* **Data Connectivity mode**:
  - Select **Import** (recommended for smaller/medium datasets and full DAX support), OR
  - Select **DirectQuery** (recommended for large scale datasets or real-time querying).

Click **OK**.

### Step 4: Authentication
When prompted for credentials:
1. Select the **Database** authentication tab on the left.
2. Enter:
   * **User name**: `YOUR_USERNAME`
   * **Password**: `YOUR_PASSWORD`
3. In the **Select which level to apply these settings to** dropdown, choose your database coordinate.
4. Click **Connect**. If prompted with an encryption support warning, verify your SSL/TLS settings according to your organization's security policy.

### Step 5: Select the Schema & Tables
1. The **Navigator** window will display available database schemas.
2. Expand the `YOUR_DATABASE` root and locate the **`public`** schema (or the schema configured in `config/pipeline.json`).
3. Select the dynamically generated analytical tables (or views) produced by Stage 6 and Stage 9.
4. A data preview will appear on the right side verifying the columns and rows.

### Step 6: Load or Transform Data
* Click **Load** to immediately import the tables into the Power BI semantic model.
* Click **Transform Data** to open the **Power Query Editor** to verify column data types, set relationships, or configure parameters before final load.

## 3. Import Mode vs. DirectQuery Mode

Power BI provides two primary connectivity modes for PostgreSQL. Choose the mode matching your analytical requirements:

| Dimension | Import Mode | DirectQuery Mode |
| :--- | :--- | :--- |
| **Data Storage** | Data is ingested into Power BI's in-memory columnar engine (VertiPaq). | Data remains strictly inside PostgreSQL; no data is cached in Power BI. |
| **Performance** | Extremely fast query and visualization response times due to in-memory compression. | Dependent on PostgreSQL server performance, network latency, and indexing. |
| **DAX Capabilities** | Full support for all DAX functions, including complex window and time-intelligence calculations. | Limited DAX support (some functions restricted or translated into SQL). |
| **Data Freshness** | Refreshed on a schedule or triggered manually (snapshot in time). | Near real-time; visuals trigger dynamic SQL queries against PostgreSQL. |
| **Resource Usage** | Consumes Power BI Desktop / Service memory and file size limits (e.g. 1 GB per dataset in Power BI Pro). | Minimal memory footprint in Power BI; shifts analytical compute load onto PostgreSQL. |
| **Recommended For** | Dashboards requiring complex calculations, sub-second visual responsiveness, and periodic updates. | Very large datasets exceeding memory quotas, or operational telemetry requiring live queries. |

---

## 4. Connection Troubleshooting

* **Remote Access Denied**: Ensure `pg_hba.conf` on your PostgreSQL server allows connections from your workstation's IP address.
* **Firewall / Port Block**: Verify that port `5432` is open on the PostgreSQL host firewall.
* **Certificate / SSL Errors**: If SSL is disabled on your local PostgreSQL server, uncheck "Enable SSL Certificate Verification" in Power BI Desktop options, or configure a self-signed certificate appropriately.
